The fictional projects in the examples are not separate released software. Their illustrative licensing text does not change this repository's MIT license.

## What to check in another project

1. Read the actual license and rights holder's declaration. Do not infer MIT when none exists.
2. Link a short README summary to the actual license file; ensure any badge agrees.
3. Identify separate terms for code, documents, images, fonts, or data when applicable.
4. Use real names, years, and required notices after the owner chooses a license.
5. Distinguish linking a source from reproducing or modifying it. Check the terms of material you copy.

## Example wording

Use this shape only when the linked files exist and their scope is established:

```markdown
## License

The source code is licensed under [the selected license](LICENSE).
Third-party assets and their notices are listed in [Credits](docs/credits.md).
```

A Credits file is not mandatory for every project. Create a real record when third-party material needs one, rather than copying a broken link from an example. Templates must not choose a license on behalf of the project owner.

Primary references: [MIT](https://choosealicense.com/licenses/mit/), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), [Awesome README's CC0 declaration](https://github.com/matiassingers/awesome-readme/blob/master/readme.md#license). A collection's terms do not automatically apply to the projects or images it links.
