# Established repository patterns

[Research index](README.md)

Actual README bodies were read on 2026-11-10. Default-branch links can change. Examples were not executed, and maintenance history was not audited. Interpretation is separated from observation.

| Repository | Observation | Application |
| --- | --- | --- |
| [torvalds/linux](https://github.com/torvalds/linux#readme) | Routes readers by role to Documentation. | A large repository can use its root as a documentation map. |
| [microsoft/vscode](https://github.com/microsoft/vscode#readme) | Distinguishes Code - OSS from the product and links contribution/support paths. | Separate product users from source contributors. |
| [kubernetes/kubernetes](https://github.com/kubernetes/kubernetes#readme) | Separates using and developing, with support/governance links. | Identify different readers’ first actions. |
| [rust-lang/rust](https://github.com/rust-lang/rust#readme) | Links installation, source builds, help, contribution, licensing, and trademarks. | Link detailed procedures rather than duplicating them. |
| [fastapi/fastapi](https://github.com/fastapi/fastapi#readme) | Embeds setup and extended examples alongside sponsorship/testimonials. | Length alone is not a failure; assess first-task discoverability. |
| [cli/cli](https://github.com/cli/cli#readme) | Organizes installation and verification by platform and links a manual. | Separate distribution paths while retaining essentials. |
